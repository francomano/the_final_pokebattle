# Contributing to The Final PokéBattle

Thanks for your interest in contributing! This document outlines how to get started and what's planned next.

---

## Getting Started

1. Clone the repository
2. Place a legally obtained GBA ROM (`.gba`) in the project root
3. Install dependencies: `pip install pygame`
4. Run: `python src/frontend.py` (assets are generated on first launch)


---

## Project Conventions

- **Maps** are defined in `data/maps.json` (layout strings, portals, NPCs, walkable tiles)
- **Tiles** are 16×16 pixel art, rendered at 48×48 (3× scale)
- **Sprites** follow naming: `player_{color}_{direction}.png`, `npc_{role}.png`, `tile_{name}.png`
- **Game state** flows through `GameSession` — all logic lives in `game.py`, rendering in `frontend.py`
- **Assets** are generated at runtime from the ROM — never commit the `assets/` folder

## Technical Considerations

- **ROM dependency**: The game needs a ROM for creature data and sprite extraction. Long-term goal: replace with an open JSON database so the ROM becomes optional.
- **Asset generation**: All sprites (creatures, players, NPCs, tiles, map backgrounds) are extracted/generated from the ROM at runtime. The `assets/` folder is gitignored — contributors must run the game once to generate it.
- **Map backgrounds**: Pre-rendered PNGs are generated by the sprite extractor from ROM tileset data combined with our map layouts.
- **Battle balance**: Current damage formula matches Gen III. Any new mechanics should document their formula in code comments.
- **State machine**: Adding new game states (SHOP, EVOLUTION, MENU) should follow the existing pattern in `GameSession.state`.
- **No proprietary content in repo**: Never commit ROM files, extracted sprites, or binary data. The `.gitignore` enforces this.
- **Map tile referencing**: The current map renderer uses hardcoded metatile IDs from the ROM's General and Viridian Forest tilesets. These references need improvement — many tiles (bridge, cut tree, signs) are approximations. Contributors should explore the ROM's tileset data to find better-matching metatile IDs for each map element. See `custom_map_1_forest/` for current renders.

## Known Issue: Map Layout Needs Rework

The current map set (`custom_map_1_forest/`) is a **first draft** — functional but rough. The main issues to fix:

| Problem | Files involved | Notes |
|---------|---------------|-------|
| Tile matching is approximate | `src/map_renderer.py` (`TILE_MAP_*` dicts) | Metatile IDs (e.g. `0x003`, `0x071`) were picked by visual inspection. Many don't perfectly match the intended look. |
| Layout grids are hand-drawn | `data/maps.json` (`layout` arrays) | Each map is a grid of ASCII chars. Proportions, paths, and decorations need polish. |
| Sign/NPC placement | `data/maps.json` (`signs`, `npcs`) | Some hints are on NPCs because sign tiles blend with the background on certain terrains. |
| Bridge/river geometry | `data/maps.json` (`river_area` layout) | The bridge is a single-tile-wide column; water boundaries are basic. |
| Cave & house interiors | `data/maps.json` (`cave_interior`, `house_interior`) | Minimal rectangular rooms with placeholder furniture. |

**Key files to edit:**
- `data/maps.json` — all map layouts, NPC positions, sign texts, portals, items
- `src/map_renderer.py` — ROM metatile ID mapping (`TILE_MAP_FOREST`, `TILE_MAP_CAVE`, `TILE_MAP_HOUSE`)
- `output_maps/` → `assets/custom_map_1_forest/` — re-render after changes with `python src/map_renderer.py`

Contributions that improve the visual quality of the maps (better tile IDs, more natural layouts, decorative variety) are highly encouraged!

## Pull Request Guidelines

1. One feature or fix per PR
2. Test that the game runs end-to-end (spawn → cut → battle → win)
3. Update `data/maps.json` schema docs if adding new tile types
4. Keep commits atomic and descriptive
5. Verify with `git status` — no assets, ROMs, or binary data in commits
